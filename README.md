### Document Searcher — Кроссплатформенная система контекстного поиска по документам

**Репозиторий:** [github.com/Macsik121/document-searcher](https://github.com/Macsik121/document-searcher) | **Стек:** Rust (`Tokio`, `lopdf`), OCR (`Tesseract`, `WinRT`), HTML/JS, GTK4

Прикладное десктопное (GUI) и консольное (CLI) приложение под **Windows 10/11, ALT Linux и Ubuntu**, созданное для решения реальной производственной задачи — быстрого поиска текста внутри локальных архивов `.docx` и `.pdf` (включая отсканированные документы без текстового слоя).

* **Системный анализ и Spec-Driven подход:** провёл анализ рабочего процесса, составил единую техническую спецификацию v2.0 (**SRS, BPMN, UML, ERD**) и с помощью AI-агентов реализовал по ней архитектуру на языке **Rust**, покрыв ядро модульными тестами (`cargo test`, статический анализ `clippy`).
* **Трёхуровневый конвейер парсинга PDF (`3-Tier PDF Extractor`):** спроектировал каскадное извлечение текста — прямой разбор кириллических шрифтовых таблиц (`/Differences`, `/ToUnicode`, `CP1251`, `UTF-16BE`) через `lopdf`, резервный парсинг через `pdf-extract` внутри защитного контура `std::panic::catch_unwind` и автоматический **OCR-фоллбэк** для сканов через `pdftoppm` + `tesseract` (`eng+rus`) или встроенный системный движок **Windows WinRT OCR**.
* **Производительность и многопоточность:** реализовал параллельную обработку файлов на всех ядрах CPU через пул `tokio::task::JoinSet` с ограничением семафором, кэширование извлечённого текста в оперативной памяти (`In-Memory TEXT_CACHE` по ключу `путь + размер + mtime`) для мгновенного повторного поиска и защиту от лавины запросов при вводе (**debounce 300 мс** + отмена устаревших задач через `CancellationToken`).
* **Кроссплатформенный интерфейс (GUI + CLI):** объединил в одном бинарном файле консольные команды (`scan`, `search`) и графический режим (локальный HTTP-сервер + окно браузера в режиме `--app`, системные диалоги `Win32` / `zenity` / `kdialog`, а также альтернативный нативный интерфейс на **GTK4 / Libadwaita**).
